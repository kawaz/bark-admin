# 管理 UI のデザイン (作業ログ)

`public/` と `src/pages/add.ts` の見た目・構造・動線の判断記録。画面の要件は [DESIGN.md](../DESIGN.md) の「画面」が正本で、ここはその見せ方だけを扱う。

## 前提

- 利用者は kawaz 1 人。自分の iPhone / iPad に通知を送るための管理画面で、tailnet 内からだけ開く
- 開く環境は Mac のブラウザ (幅 1280 前後) と iPhone の Safari (縦、幅 390)。対象は最新の Chrome と Safari だけ
- 主役はデバイス一覧。通知テストは一覧で絞った宛先へ送る確認用で、毎回触るのは title / body と数項目
- 招待ページは QR を読んで iPhone で開く 1 画面で、やることは「Bark で開く」を押すことだけ

## 主題から決めたこと

この画面の中心にある概念は「宛先」。フィルタで宛先を絞り、一覧がその宛先を見せ、通知テストがその宛先へ送る。3 つの部品が同じ「宛先」を共有していることが見て分かれば、フィルタの意味を文章で説明しなくて済む。

そこで、**宛先を表す色を 1 つだけ持ち、宛先に関わる部品にだけ使う**。蛍光ペンの黄色で、紙に宛名へ線を引く感覚に寄せた。色が付くのは次の 4 か所だけ:

- フィルタ欄 (宛先を決める所)
- 一覧のタグのうち、フィルタに一致したもの (なぜその端末が宛先に入ったかの理由)
- 一致した台数
- 送信ボタン「n 台へ送る」(宛先へ送る所)

それ以外はインクの濃淡だけで組む。色が情報そのものなので、装飾の色は持たない。

## Color

| 名前 | light | dark | 役割 |
|---|---|---|---|
| paper | `#F5F6F8` | `#16181D` | 地 |
| surface | `#FFFFFF` | `#1F2228` | 入力欄・ダイアログ |
| ink | `#1A1D24` | `#E8EAEE` | 本文、主ボタンの地 |
| muted | `#646B78` | `#9AA1AD` | 補足・日時・device_id |
| line | `#DADDE3` | `#30343C` | 行の区切り・枠 |
| marker | `#FFE45C` | `#F2C94C` | 宛先 (上の 4 か所だけ) |
| danger | `#C2362B` | `#FF7A6E` | 退役 |

すべて `light-dark()` で 1 つの custom property にまとめる。marker の上の文字は両モードとも ink の light 値 (`#1A1D24`) で、地の明るさに関わらずコントラストを保つ。

## Type

- 本文も見出しも `"Hiragino Sans", "Hiragino Kaku Gothic ProN", -apple-system, system-ui, sans-serif` の 1 系統。Mac と iPhone のどちらにも入っていて、Web フォントを外から引かずに済む。ヒラギノの欧文は SF より字幅が広く、`iphone` `kawaz` のような短い英小文字の名前を大きく組んだ時に形がはっきり出る
- 固定幅 (`ui-monospace`) は **人が文字を 1 字ずつ照合するもの** だけに使う: device_id、device_token、暗号化キー、`key=value` を書く入力欄。小さなラベル一般には使わない
- スケールは 16px 基準の 1.25 比: 13 / 16 / 20 / 25 / 31。入力欄は iOS Safari のフォーカス時ズームを避けるため 16px を下回らせない
- 書体を表現に使うのは一箇所だけ: 一覧と詳細の **端末名** を 20〜31px の太字で組み、owner と device_id はその脇に小さく従える。人は端末を「kawaz の iphone」で覚えていて、device_id では覚えていないので、名前が一覧の見出しになる

## Layout

Mac 幅 (コンテナ幅 64rem 以上) は 2 列。左が宛先と一覧、右が通知テスト。右列は `position: sticky` で、一覧をスクロールしても送信ボタンと「宛先」の表示が見えたままになる。

```
bark-admin
┌──────────── 宛先と一覧 (広い) ───────────┐ ┌──── 通知を送る (sticky) ────┐
│ 宛先 [owner=kawaz            ]  3 台     │ │ 宛先 owner=kawaz  3 台      │
│ □ 退役済みも表示                         │ │ title    [               ]  │
│                                          │ │ body     [               ]  │
│ デバイス                 [デバイスを追加]│ │ level [v]   sound [      ]  │
│ iphone  kawaz  family=kawazu …   10-20   │ │ ▸ ほかの項目                │
│ DuMUEQ…                                  │ │ [ 3 台へ送る ]              │
│ ipad    kawaz  room=living … +3  10-18   │ │ 結果: iphone 送った / …     │
└──────────────────────────────────────────┘ └─────────────────────────────┘
```

iPhone 幅は 1 列に積む。順序は 宛先 → 一覧 → 通知を送る。通知テストの側にも宛先の写しと台数を出すので、フィルタから離れた位置でも送り先が分かる。

```
bark-admin
宛先 [owner=kawaz      ] 3 台
□ 退役済みも表示
デバイス        [デバイスを追加]
iphone            kawaz
DuMUEQLh…        10-20 10:02
family=kawazu  model=…
──────────────
…
通知を送る
宛先 owner=kawaz  3 台
title / body / level / sound
▸ ほかの項目
[ 3 台へ送る ]
```

- 揃えは全部左揃え。中央揃えは招待ページの QR だけ
- 一覧は `<ul>` + CSS grid の subgrid。広い時は列が揃った表に見え、狭い時は 1 台ずつのブロックに組み替わる。切り替えは viewport でなく一覧自身の幅 (`@container`) で決める
- 一覧のタグは押すとフィルタに足す (もう一度押すと外す)。フィルタを手で書かなくても一覧から宛先を作れる
- デバイス追加は一覧の見出し行のボタンから `<dialog>` で開く。招待は頻繁に作らないので TOP の面積を割かない。ダイアログは invoker commands (`commandfor` / `command`) で開閉し、`closedby="any"` で外側タップと Esc で閉じる
- 通知テストの 20 項目のうち title / subtitle / body / level / sound を常に出し、残りは `<details>` に入れる。閉じたままでも入力済みの数が summary に出る
- 送信結果は端末名ごとに「送った / 失敗 (理由)」で並べる。生の応答は結果の下の `<details>` に残す
- 暗号化は色を持たない。一覧では端末名の下に muted の「暗号化」を添えるだけ。鍵は詳細と招待ページで、固定幅の枠 + コピーボタンの 1 行に置く (Bark の設定欄へ手で貼るもの)。招待ページでは「Bark で開く」の次、App Store の前に置く

## Principles

- 宛先の色は宛先のためだけに使う。他の強調に流用しない
- 端末は名前で呼ぶ。device_id は照合用の脇役
- 1 画面に置く判断は 1 つ。TOP は「誰に送るか」、詳細は「この端末をどう呼ぶか / 暗号化するか / 外すか」、招待ページは「Bark で開く」
- 文言は常体で短く、ボタンは動詞。結果の文言はボタンと同じ動詞で返す (「送る」→「送った」)
- 品質の床: 幅 390 で横スクロールが出ない、キーボードのフォーカスが見える (`:focus-visible`)、`prefers-reduced-motion` で動きを止める、light / dark 両対応

## 避けた default

| default | 代わりにしたこと |
|---|---|
| iOS 風の青アクセント (旧 UI の `#0a66d6`) を全ボタンに | 色は宛先の 4 か所だけ。他のボタンはインクの地 |
| インディゴ / バイオレットのアクセント (最初の案。どの管理画面にもある Tailwind 系の色に寄っていたので捨てた) | 蛍光ペンの黄色を「宛先」の意味に限定 |
| 生成 UI に多い温かいクリーム地 + テラコッタ、黒地 + 蛍光 1 色 | 冷たいグレーの紙とインク |
| 同じ角丸カードに全部を詰めて同じ影を落とす | 一覧は罫線で区切った行。影はダイアログだけ。角丸は部品の大きさで変える (タグ 6px / 入力とボタン 8px / ダイアログ 14px) |
| `<table>` をそのまま狭い画面に出して横にはみ出す (旧 UI は幅 390 で 687px に広がっていた) | subgrid + container query で行をブロックに組み替える |
| 20 項目を全部並べたフォーム | 5 項目 + `<details>` |
| 台数を大きな数字 + 小さなラベルで飾る | 台数は宛先の文と送信ボタンの中に置く |
| 全見出しの上の英字大文字ラベル、`A · B · C` の区切り、ボタン末尾の `→` | 使わない |
| `alert()` / 生 JSON の `<pre>` で結果を返す | 結果は端末名ごとの行。エラーは入力欄の下に原因と直し方 |

## スクリーンショットでの自己批評で直した点

幅 1280 (Chromium) と幅 390 (WebKit の iPhone 13 エミュレーション) で撮って見直した。

- 宛先の写しで「宛先」と「全台」が 1 つの文字列に繋がって読めた → 別要素にして間隔を取る
- `<details>` の summary を flex にしたら開閉の三角が消えた → 既定の `list-item` のまま使う
- 招待ページの「Bark で開く」が幅 100% + padding で画面の右にはみ出した → ボタンを `box-sizing: border-box` に
- 退役済みの行を丸ごと薄くしたら「退役 日時」の赤まで薄くなった → 名前の色だけ muted にして、退役の表示は濃いまま
- タグの無い端末で日時が tags の列へ詰まった → 広い時の列を明示で固定する
- 詳細画面で device_id (固定幅) と登録日時 (本文) の大きさが揃わず段差が出た → `dd` の大きさを揃え、`dt` / `dd` を baseline で揃える

## 残っている点

- iOS Safari の `<select>` は `appearance` を外さない限り高さ指定が効かず、隣の入力欄より低く見える。`appearance: base-select` (customizable select) が Safari に来たら揃える
- 通知テストの列は sticky なので、「ほかの項目」を開いて列が画面より高くなり、かつ一覧がそれより長い時は、送信ボタンが一覧の末尾までスクロールしないと見えない。台数が 1 桁の前提では起きない

## 使う機能 (Chrome / Safari の最新で確認)

`light-dark()`、CSS nesting、`@container`、subgrid、`:has()`、`field-sizing: content`、`<dialog>` + invoker commands (`commandfor` / `command`) + `closedby`、`@starting-style`、`::details-content`、`Map.groupBy`。Playwright の WebKit (Safari 26 系) と Chromium で `CSS.supports` / プロパティの存在を確認済み。
